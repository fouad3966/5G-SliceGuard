5G Network Slicing & Why It Needs Guarding

5G network slicing allows operators to create multiple virtual networks (slices) on a single shared physical infrastructure. Each slice is an isolated, end-to-end virtual network tailored for a specific use case — with its own bandwidth, latency guarantees, and security policies. Think of it as separate lanes on a highway: same road, but each lane has different speed limits and rules.

Why This Matters for Security

An IoT slice (mMTC) might have thousands of easily-compromised sensors. A medical slice (URLLC) handles remote surgery with sub-1ms latency requirements. If an attacker compromises an IoT device and jumps to the URLLC slice, lives are at risk. That's why slice isolation — and SliceGuard — is critical.

Defense Mechanism

The "Highway" Analogy: How SliceGuard Operates

A 5G Network is a massive highway. Slices are dedicated lanes, and PDU Sessions are the individual cars. Watch how our ML Engine identifies and quarantines rogue vehicles without shutting down the entire infrastructure.

What the ML IDS is Monitoring

1. Volumetric Features

Total bandwidth (Mbps) and Packet Rate (pps). Spots brute-force floods.

2. Infrastructure Status

CPU and Memory usage of the UPF virtual machines.

3. QoS Degradation

Latency, Jitter, and Drops. Critical for ensuring URLLC slices don't crash.

4. Cross-Slice Correlation

Analyses a 10-second rolling correlation: if mMTC CPU spikes exactly when URLLC latency spikes, it proves a physical hypervisor attack.

The Scalpel, Not The Shield

When flagged, the ML doesn't shut down the whole mMTC lane. It commands the SMF (Session Management Function) to target only rogue PDU Sessions. The attacker is dropped, but innocent cars keep driving safely.

Defense Engine

SliceGuard Dual-Model Architecture

A multi-model machine learning pipeline integrated at the 5G Core. It extracts per-flow UPF telemetry and utilizes both supervised algorithms and unsupervised isolation forests to autonomously trigger the SMF.

UPF Data Plane

Continuous Per-Flow Telemetry. Monitors PDU sessions deep inside the GTP-U Tunnels.

Feature Engineering Engine

Calculates QoS, Infrastructure, and Cross-Slice correlations across a 10-tick rolling window.

XGBoost Classifier

Supervised. Extremely fast detection of known Resource Theft logic.

Isolation Forest

Unsupervised. Catches Zero-Day anomalies & stealthy Side-Channels.

SMF Executive API

Automated PDU Quarantine. Drops attacker IDs instantly while preserving innocent slice traffic.

Threat Landscape

Threats SliceGuard Defends Against

SliceGuard is built to detect and neutralize threats that exploit shared physical infrastructure to breach the isolation boundaries between virtualized network slices.

1

Reconnaissance

The attacker gains access to a low-security slice (e.g., mMTC). They probe the shared infrastructure to identify resource contention points and slice topology information.

2

Resource Mapping

Using timing side-channels and traffic analysis, the attacker maps shared resources: CPU cores, memory banks, network buffers, and hypervisor interfaces across slices.

3

Isolation Breach

The attacker exploits vulnerabilities — shared VNF bugs, hypervisor escapes, or API flaws — to cross the slice boundary and access the target slice's resources.

4

Exploitation

Once across the boundary: steal bandwidth (resource theft), inject malicious packets (data injection), or exfiltrate sensitive data from the critical URLLC slice.

5

Impact

The compromised URLLC slice experiences latency spikes, potentially causing autonomous vehicle failures, surgical robot malfunctions, or industrial control disruptions.
