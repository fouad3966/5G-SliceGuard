5G Network Slicing & Why It Needs Guarding

5G network slicing allows operators to create multiple virtual networks (slices) on a single shared physical infrastructure. Each slice is an isolated, end-to-end virtual network tailored for a specific use case — with its own bandwidth, latency guarantees, and security policies. Think of it as separate lanes on a highway: same road, but each lane has different speed limits and rules.

Why This Matters for Security

An IoT slice (mMTC) might have thousands of easily-compromised sensors. A medical slice (URLLC) handles remote surgery with sub-1ms latency requirements. If an attacker compromises an IoT device and jumps to the URLLC slice, lives are at risk. That's why slice isolation — and SliceGuard — is critical.

Defense Engine

End-to-End IDS Defense Pipeline

From uncovering core hypervisor vulnerabilities to executing targeted PDU quarantine via REST APIs, this is the exact flow of the dual-model architecture.

The Core Vulnerability

Network slices share physical Hypervisor hardware. Attackers exploit this by flooding a low-security slice (mMTC) to mathematically steal CPU/Memory from critical slices (URLLC), risking autonomous vehicle accidents or physical infrastructure failures.

Flow-Level Monitoring (UPF)

The IDS sits seamlessly at the 5G Core. It doesn't treat slices as opaque pipes. It performs flow-level extraction directly on the UPF, categorizing all traffic by individual PDU Sessions mapped to distinct IP or SUPI device IDs.

Feature Engineering

The engine monitors features (Volumetric, Infrastructure, QoS) over rolling time windows. Crucially, it calculates Cross-Slice Correlation: mathematically proving that when mMTC volumetric stats spike, URLLC QoS latency degrades simultaneously.

Dual-Model Machine Learning

XGBoost (Supervised): Instantly classifies known signatures like massive Resource Theft or Data Injections.

Isolation Forest (Unsupervised): Mathematically acts as a safety-net to isolate zero-day anomalies and stealthy cache-timing Side-Channels.

Automated Quarantine (REST APIs)

The IDS acts as a scalpel. Instead of shutting down the whole mMTC slice, it identifies the exact corrupted PDU tracking IDs. It fires an urgent HTTP POST request (SBA API) commanding the SMF (Session Management Function) to forcefully drop exclusively those rogue PDU connections.

System Restoration

The malicious traffic physically drops before it reaches the core. The hypervisor CPU buffers drain automatically, and the critical slices instantly restore to standard sub-1ms communication latencies.

Threat Landscape

Threats SliceGuard Defends Against

SliceGuard is built to detect and neutralize threats that exploit shared physical infrastructure to breach the isolation boundaries between virtualized network slices.

1

Reconnaissance

The attacker gains access to a low-security slice (e.g., mMTC). They probe the shared infrastructure to identify resource contention points and slice topology information.

2

Resource Mapping

Using timing side-channels and traffic analysis, the attacker maps shared resources: CPU cores, memory banks, network buffers, and hypervisor interfaces across slices.

3

Isolation Breach

The attacker exploits vulnerabilities — shared VNF bugs, hypervisor escapes, or API flaws — to cross the slice boundary and access the target slice's resources.

4

Exploitation

Once across the boundary: steal bandwidth (resource theft), inject malicious packets (data injection), or exfiltrate sensitive data from the critical URLLC slice.

5

Impact

The compromised URLLC slice experiences latency spikes, potentially causing autonomous vehicle failures, surgical robot malfunctions, or industrial control disruptions.
