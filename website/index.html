5G Network Slicing & Why It Needs Guarding

5G network slicing allows operators to create multiple virtual networks (slices) on a single shared physical infrastructure. Each slice is an isolated, end-to-end virtual network tailored for a specific use case — with its own bandwidth, latency guarantees, and security policies. Think of it as separate lanes on a highway: same road, but each lane has different speed limits and rules.

Why This Matters for Security

An IoT slice (mMTC) might have thousands of easily-compromised sensors. A medical slice (URLLC) handles remote surgery with sub-1ms latency requirements. If an attacker compromises an IoT device and jumps to the URLLC slice, lives are at risk. That's why slice isolation — and SliceGuard — is critical.

Defense Engine

End-to-End IDS Defense Pipeline

From the core NFV vulnerability to automated PDU quarantine, this is the complete lifecycle of SliceGuard's dual-model intrusion detection and response architecture.

1 — The Core Vulnerability

5G networks use NFV (Network Function Virtualization) to run multiple slices on the same physical hardware, managed by a shared Hypervisor. Because slices share CPU, RAM, and NIC resources, Cross-Slice Attacks are possible: an attacker flooding the mMTC slice can exhaust the hypervisor's CPU, causing URLLC packet delays that could crash an autonomous vehicle's braking system.

2 — IDS Positioning: Per-PDU Flow Monitoring

The IDS integrates directly at the UPF (User Plane Function) inside the 5G Core. It does not treat a slice as one opaque tunnel. Instead, it performs Deep Packet Inspection and Flow Analysis on individual connections:

  • Every device communicates via its own PDU Session (encapsulated in a GTP-U tunnel).
  • The UPF tracks each session by the device's IP address and SUPI (Subscription Permanent Identifier) — the 5G-unique device ID.
  • This gives the IDS per-device visibility inside a slice containing millions of flows.
INTERACTIVE VISUALIZATION: PDU SESSIONS INSIDE A SLICE

Each slice has multiple PDU sub-lanes. Each car is a device flow tracked by its IP / SUPI. Zombies flood specific PDUs — the SMF firewall targets only those lanes.

3 — Feature Engineering (What the ML "Sees")

Unlike a basic firewall that only checks ports and IPs, the ML engine continuously extracts statistical "vital signs" grouped into four categories:

  • Volumetric: Total bandwidth (Mbps) and packet rate (pps) — spots brute-force floods.
  • Infrastructure: CPU and Memory usage of the VNF virtual machines — detects resource starvation.
  • QoS Degradation: Latency, Drop Rate, and Jitter — jitter is the #1 indicator of stealthy side-channel attacks.
  • Temporal & Cross-Slice: Over a 10-second rolling window, the engine calculates the standard deviation, deltas, and the cross-slice correlation score. If mMTC CPU spikes exactly when URLLC latency degrades, this mathematically proves a hypervisor-level attack rather than a normal traffic surge.

4 — Dual-Model ML Detection

The extracted features are fed simultaneously into two complementary models:

  • XGBoost (Supervised): Trained on labelled datasets of known attack signatures (Resource Theft, Data Injection). Acts as an ultra-fast classifier recognizing complex non-linear patterns with high confidence.
  • Isolation Forest (Unsupervised): The safety net for Zero-Day attacks. It doesn't look for specific signatures — it mathematically isolates any behavior that deviates from baseline. If a brand-new exploit appears, the anomaly score instantly spikes.

When combined confidence exceeds 65%, the system triggers automated quarantine.

5 — Automated Quarantine via REST API

Human reaction time is too slow for URLLC. The IDS autonomously executes a surgical quarantine:

  • The Scalpel (Session Termination): The IDS pinpoints the specific rogue SUPI/IP identifiers. It sends an HTTP POST via the 5G SBA to the SMF (Session Management Function). The SMF forcefully terminates the misbehaving PDU sessions — not the physical devices.
  • Why PDU Termination? Dropping an entire session is instantaneous and highly secure. While any legitimate "clean" background packets mixed in that specific session are also dropped (a harsh but necessary measure), avoiding slow packet-by-packet filtering is the only way to save the critical URLLC slice from crashing during a massive flood.
  • Zero Slice Interruption: The malicious sessions are terminated instantly, but the other 9,900 legitimate devices in the exact same slice experience zero interruption because they have their own independent PDU sessions.

6 — System Restoration

Because the malicious PDU sessions are dropped at the SMF level, the flood physically stops entering the core. The hypervisor CPU buffers drain, and the URLLC slice is instantly restored to sub-1ms latency.

What happens to the terminated sessions? The devices are now disconnected from the data plane. The network operator can choose to permanently blacklist the device's SUPI, or place it in a remediation pool to be scanned. Once verified clean, the device is allowed to re-attach and establish a brand new, clean PDU session.

Threat Landscape

Threats SliceGuard Defends Against

SliceGuard is built to detect and neutralize threats that exploit shared physical infrastructure to breach the isolation boundaries between virtualized network slices.

1

Reconnaissance

The attacker gains access to a low-security slice (e.g., mMTC). They probe the shared infrastructure to identify resource contention points and slice topology.

2

Resource Mapping

Using timing side-channels and traffic analysis, the attacker maps shared resources: CPU cores, memory banks, network buffers, and hypervisor interfaces across slices.

3

Isolation Breach

The attacker exploits vulnerabilities — shared VNF bugs, hypervisor escapes, or API flaws — to cross the slice boundary and access the target slice's resources.

4

Exploitation

Once across the boundary: steal bandwidth (resource theft), inject malicious packets (data injection), or exfiltrate sensitive data from the critical URLLC slice.

5

Impact

The compromised URLLC slice experiences latency spikes, potentially causing autonomous vehicle failures, surgical robot malfunctions, or industrial control disruptions.
